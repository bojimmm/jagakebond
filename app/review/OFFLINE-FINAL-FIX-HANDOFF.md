# Offline, metadata and release-correctness handoff

Scope: staged frontend only; production was not touched. Web gallery metadata now preserves missing EXIF capture time as unknown, never substitutes file modification time or current device location/weather, accepts finite zero coordinates, and treats absent EXIF positioning error as unknown accuracy. Gallery capture metadata is snapshotted separately from live telemetry; EXIF time is explicitly labeled with unknown source timezone, and manual times use the device IANA timezone label. Camera capture snapshots the actual capture-time metadata. Upload metadata and farm association derive from the immutable snapshot; the UI does not block capture when EXIF time is missing. Auth gate selectors now correctly target the shell/nav.

All web uploads route through the durable single-flight outbox with the stable request ID; retry uses the stored ID and lost responses replay idempotently. Before POST, web sync GETs `/api/health` and accepts only a numeric `2.x.y` version with minor >= 1. Unknown/older versions leave drafts pending and surface “Server perlu diperbarui”; the browser mock uses explicit 2.1.0 and adds an older-version no-POST assertion. HTTP 400/413 mark a durable failed row, 409 retains the draft, and 429 observes Retry-After (bounded to one hour; one-minute minimum). Native image reads use a generation guard across `revokeImages`; native bridge JSON string bodies are parsed. Native sign-in activates the native outbox, native receipt recovery/list uses native rows, and manual retry activates matching account instead of invoking web sync. Successful job acknowledgement is conditional on saved record.

Map default is attributed OSM standard tiles; no satellite provider is configured. Tile attribution links to OSM copyright. Service worker no longer caches/prefetches any map tiles; map requests use normal browser networking/caching policy. `frontend/index.html` labels the map “Peta dasar”.

Current verification: `node --check` on app.js, offline-sync.js, native-adapter.js, sw.js and `git diff --check` passed after the latest edits. Direct Python scripts passed confidence gate 64/64, foundation 82/82, API contract and queue hardening. `python -m unittest discover` is unsuitable because two legacy test scripts call `sys.exit(0)` at import; direct scripts were used instead. The IndexedDB browser test initially passed baseline response-loss coverage, then the added older-server test exposed a fixture interaction; its assertion was corrected to remove the extra pending row before checking retry count, but a rerun timed out at the tool layer and is unverified. `python ../review/run_browser_acceptance.py` last reported 20/21 with two `Cannot read properties of null (reading 'lat')` errors before the later stamp-metadata correction; no successful rerun exists. Therefore the real HTTP acceptance gate is NOT green/verified.

Not yet implemented/verified: comprehensive safe JS-string + HTML-attribute encoding for inline handlers and malicious-ID/name XSS regressions; null-prototype/Map grouping and candidate dedupe; full per-row offline draft actions/render/failed/409 UX (latest patch added basic row list and discard confirm, but rerender/action behavior untested); complete dialog focus/Escape/restore audit (handlers added, but several modal close functions and inert underlying controls still need a full audit); EXIF 0,0/altitude zero/no-lastModified tests; account-switch-during-photo-load, record-save failure/no-ack, 401/429/failed-row, native generation/recovery and current parent fixture tests. Map OSM switch and service-worker policy likewise need current UI/browser run. Do not treat this handoff as a release sign-off.
