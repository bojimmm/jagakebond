# 0.2.3.0 security continuation (2026-10-29)

> **Release** 0.2.3.0 · **Status** shipped

The merged branch originally passed its Android build but only 60/62 regression
suites. Failures were the web polling badge check and the UX relative-date check.
Production was independently read back as 0.2.2.3 during this continuation.

The owner explicitly chose to allow Google sign-in for admins. Existing admin
roles, seven-day sessions and password confirmation for sensitive actions remain.

## Fixed findings

1. Nonce flood: a transaction enforces 20 live nonces per normalized IP alongside
   the 5000 global cap; IPv6 /64 addresses share a budget. Expiry releases slots.
2. Registration flood/retention: 20 new requests per normalized IP per 24 hours,
   persisted in SQLite. Refreshing a pending request does not spend another slot.
   Pending requests expire 30 days after creation even if refreshed; decided
   requests are preserved. Hourly retention purges expired IP budget rows.
3. Unsafe email linking: persisted creation provenance and password-session
   history gate auto-linking. Self-registration counts as password use. Legacy
   unknown history is treated conservatively. Admin-created accounts, including
   admins, remain eligible after password login. A linked identity cannot be
   replaced by another subject. Lookup/conflict checks/insertion are atomic.
4. Cold JWKS outage: fetch outside the lock, share one in-flight fetch, cache
   failures for 10 seconds, use 5-second HTTP and 2-second connect timeouts.

Related low findings addressed: atomic link conflict handling, token/nonce
failure audit without credentials, and independent Google/password throttles.
Non-finite token timestamps and malformed JWKS are also handled safely.

The two browser assertions now account for a photo crossing local midnight and
wait for the result workflow to render the badge before checking it.

## Verification and remaining limits

Focused Google API test: **152/152 assertions passed** on the sandbox. Includes
concurrent nonce requests, competing identity links and eight concurrent cold
JWKS requests during an outage. Synthetic data and locally generated keys only.

Full regression/build label: `g0230-security-final`. Read back and verified:
`REGRESSION 62 62 62 [] changed: []`, regression exit=0. Android testDebugUnitTest,
lintDebug, assembleDebug and assembleRelease finished successfully with exit=0.
The final package verification records the exact JVM and lint counts.

`ops/run_final.py` includes both Google suites. `ops/package_0230.py` requires
62 suites, source hashes, signer identity, JVM/lint results, asset byte equality,
and fresh-extraction Google security tests. Stage script hash is filled only
after successful packaging. Mutable release docs describe schema 9 -> 10 and
snapshot-only rollback; frozen releases are untouched.

Unresolved low findings from the original review: stale admin approval guards,
a UI hint for Google-only password operations, no un-reject action, and Android
cookies on config/nonce requests. These are not claimed fixed here.

Pending requests matching untrusted existing password accounts remain blocked
with email_taken on approval until ownership is resolved; accounts are not
silently merged and planted passwords/sessions are not preserved.

Real GIS/FedCM, live Google JWKS and real Android Credential Manager remain
untested. Google Cloud setup and the public Web client ID are owner dependencies.
Do not enable Google or claim real-device acceptance from synthetic tests.

Connection note: a reused VPS-to-sandbox SSH connection refused forwarding.
A fresh connection worked without restarting the sandbox. Override the inner
SSH with `-o ControlMaster=no -o ControlPath=none` when this recurs. Git Bash's
SSH helper also failed on Windows with an `exec`/PowerShell error; native Windows
OpenSSH scp worked. Neither issue required a server or signing-config change.
