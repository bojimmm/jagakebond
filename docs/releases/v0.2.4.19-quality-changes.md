# JagaKebond 0.2.4.19 quality changes

> **Release** 0.2.4.19 · **Status** shipped

This note describes the implementation and its validation boundaries. Deployment and artifact evidence are recorded separately; it is not an expert accuracy or phone acceptance certificate.

## Farmer-facing changes

- Short, shared pest/disease labels, consistent manual status handling, and coexisting findings across history, maps, daily notes and plot summaries.
- Analysis reports lead with relevant inspection steps, retain detailed findings and possible causes, support selecting/copying text, and put provider information in optional detail. Uncalibrated percentages are removed.
- Plot summaries describe recorded observations and their coverage. Repeated labels do not establish transmission; elevation does not establish humidity, a pathogen, or crop suitability.
- Daily-note saving has a pending state and an error inside the dialog that preserves the entered text.
- Dialogs keep keyboard focus within visible controls; closed map sheets are inert.
- The location editor owns its markup, includes one GPS recenter action, and reports GPS failure with recovery instructions.
- Sign-in uses shared design tokens and a current, labelled example of the real app. The initial guide is five steps and remains available from Akun.
- Map/photo libraries load when needed. Map loading has a persistent retry action. Gallery import shows preparation and prevents late metadata from restoring a cancelled photo or mixing images and coordinates.
- Includes the pending integrated plant editor and per-plant re-analysis actions in Ringkasan Petak. Original photos, crop identity, user corrections and fast quotas are preserved.

## AI workflow changes

- Incomplete or malformed results cannot overwrite a saved assessment. Worker claims have an opaque identity, expiry and renewal; stale workers cannot publish, release or trace a replacement claim.
- Total network deadlines cover headers and body reads. A diagnosis can retry once at its token ceiling. A validated result can retry saving without repeating inference.
- Health is tracked per lane. Records retain allowlisted model/request metadata and input/prompt/reference identities.
- The prompt treats photo/context as untrusted supporting evidence, minimizes location/account identifiers, and distinguishes earlier AI guesses from farmer observations. History uses the same plant and excludes the re-analysis target.
- Product targets are derived on the server from shared active problem IDs, rather than alternatives or editable browser values. Unknown coverage returns an explanation. Optional context is not advertised as a personalized prescription.
- Model-generated treatment/application text is replaced by controlled, relevant inspection tasks. The report retains photo findings and descriptive nutrition information when supported. Uncertainty does not reduce the observed urgency.
- Admins can explicitly test each distinct model route with a synthetic image and JSON challenge. Listing, basic image/JSON behavior and latency are separate from crop diagnostic accuracy.

## Evidence and external requirements

See `DESIGN.md` and `AI-EVALUATION.md`. Unit/browser tests validate software behavior, not diagnosis accuracy. Expert-labelled evaluation, reviewed crop/problem application guidance and physical Android acceptance must not be reported as completed without that evidence. Product application eligibility remains closed.

The current implementation uses release 0.2.4.19, Android versionCode 47, API compatibility 2.1.0, database schema 11 and offline shell `jk-v53`. Build, final regression, packaging and deployment status are recorded separately in the delivery report.

## Build dependency maintenance

The UI and Android build dependency locks were updated within their existing compatible ranges to address npm-reported moderate advisories. Capacitor CLI resolves to 8.6.0; Android/core remain 8.5.3. Both updated dependency audits reported zero vulnerabilities on this build host. No Python runtime manifest, production model setting or Android signing configuration changed. Preserve lockfiles and rerun the full Android checks after dependency changes.
